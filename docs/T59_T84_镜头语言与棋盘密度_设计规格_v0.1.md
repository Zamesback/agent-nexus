## 0. 一句话结论

## 2. 关键误读澄清：`objLimit` 不是「部署容量」

引擎 L2669：

```js
if (S.round >= S.pveObjLimit) { gameover(); return; }   // T28-B：PVE 目标回合数（默认 15）
```

- L2829 `S.pveObjLimit = _lv.objLimit || 15`
- 字段名 `objLimit`（objective limit）是**目标回合数**的缩写，与「同屏单位数上限」无关。
- T67「objLimit 缩表（关1-7→8、关8→10）」调的是**关卡时长目标**，不是部署容量。

**因此「部署容量」的真实约束是三项，均不在棋盘尺寸上：**

| 约束 | 实现 | 归口 |
|---|---|---|
| ① 卡库供给 | `deck:[["changq",8,1], ...]` 每兵种 8 张 | 数值线 builder6 |
| ② 金币经济 | `gold` / `S.money` 回合收入 | 数值线 builder6 |
| ③ 阵型槽位 | `findEnemySlot()` 找空位落子 | 引擎 + 数值线 |

**→ 把 `CELL` 从 30 调到 24，上述三项一个都不变，部署容量增量为 0。**

## 3. 若仍执行 T84：棋盘密度方案（设计侧规格）

### 3.1 视觉参数

| 项 | 现值 | 建议值 | 说明 |
|---|---|---|---|
| `CELL` | 30 | **24**（-20%） | 战场像素宽 420 → 336 |
| `GRID_COLS/ROWS` | 14 / 9 | **17 / 11**（可选） | 真要「更多格」才动此项，187 格；风险见 3.3 |
| 兵绘制缩放 | 1.0 | **0.8** | 与 CELL 同比例，避免兵溢出格 |

### 3.2 ⚠️ 可读性下限（缩格子会打破的两处已有优化）

**（1）个体血条 —— 最可能出问题**
planner T82/T83-b 已把血条优化为「每兵 10×3px、按兵序号三层错位、上移 1px」，其目的是让**同排兵血条不再连成一片**（同排兵间距约 13px）。
→ `CELL=24` 后间距降到约 10.4px，**10px 宽的血条必然重新连片**，T82 的优化会被打回。

建议二选一：
- **方案 A（推荐）**：`CELL=24` 时血条宽降至 8px，同时三层错位幅度从 1px 提到 2px；
- **方案 B（更省心）**：改为「仅队首显示血条 + 该兵受伤时才显示个体血条」，满血兵不画——画面更干净，且格子越小越受益。

**（2）部署反馈锚点**
T68 部署确认感（幽灵阵中锚点 + 吸附跟随 + 落点闪光）的锚点尺寸须同步 ×0.8，否则 `CELL=24` 下锚点会压到相邻格。

### 3.3 扩格（17×11）风险提示

若选择扩 `GRID_COLS/ROWS` 而非缩 `CELL`：
- 现有寻路/通路判定（`findEnemySlot`、车类 2 格宽过桥逻辑、T80 直行锁 x 修复）**全部按 14×9 验证过**，扩到 17×11 需整轮回归；
- T30「PVE 对称阵地式布阵」8 关阵型图坐标全部基于 14×9，扩格会导致阵型图失效，需 builder5 重出配置。

**建议：T84 本轮只做缩 CELL（纯视觉、零逻辑回归风险），扩格单独立项、等 T30 阵型图定稿后再议。**

## 4. T59 镜头语言规格（击杀特写 / 推近）

### 4.1 交互规格

| 项 | 普通单位击杀 | 敌将 / Boss 击杀 |
|---|---|---|
| 触发 | 单位死亡且非暴击 | `hero_*` 或 `lvbu` / `muniu` 类死亡 |
| 推近倍率 | `CAM_ZOOM_BATTLE 1.35 → 1.75` | `→ 2.0` |
| 特写时长 | 350ms | 600ms |
| 回落时长 | 250ms | 300ms |

### 4.2 实现约束（务必沿用现有手感，别另起一套）

1. **缓动统一**：用 `CAM_SMOOTH = 14` 同族指数平滑 `1 - exp(-dt·k)`，与现有相机跟手一致；特写期间把平滑系数临时降到 ~9 制造「慢推」的顿感，结束恢复 14。
2. **焦点偏移**：以被击杀单位中心为焦点，**向上偏移 0.35 格**，使兵落在画面中线偏下——否则头顶血条与伤害数字会被顶出屏幕（T82 血条又上移了 1px，更容易出屏）。
3. **与结算同帧**：伤害数字 / 血条扣减 / 死亡动画必须在**同一帧**触发特写，避免出现「先推近、后掉血」的错位感。
4. **不与用户操作打架**：`userCamActive = true`（用户正在 pinch/拖拽）时**禁用特写**，用户操作优先。
5. **连杀合并**：短窗口内（600ms）连续击杀只做一次特写，倍率取最高档，避免连续死亡时画面反复推拉造成眩晕。

### 4.3 与 T84 的绑定理由（回应看板 T84 note）

两任务绑定是对的，收益点具体化为：
- `CELL=30`（战场 420px 宽）时，×1.75 特写后单兵占屏比例已接近上限，再推就只剩马赛克；
- 缩到 `CELL=24`（336px 宽）后，×1.75 推近**仍有富余**，可以看清兵面细节（3/4 侧朝向帧、立绘细节）。

**执行顺序建议：先 T84 缩格子，再做 T59 特写**——反过来的话 T59 的倍率参数要按大格子定死，之后缩格子还得回调一次。
