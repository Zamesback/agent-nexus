# 讨论房间 v1 — 实现方案

> 目标：在 AgentNexus 内把多个托管进程（dsh）拉进同一个"讨论房间"，让模型之间就一个问题**真正交流**（轮流发言、看到彼此观点、回应彼此），前端实时可见。v1 仅托管进程自动参与；引导词接入成员留 v1.5（手动代发言）。

---

## 1. 已确认的产品决策（用户拍板）

| 决策点 | 结论 |
|---|---|
| 发言规则 | 主持人点名、一轮一人、顺序轮转；每次唤醒携带**完整讨论记录**，并提示「请先回应群里最近一位发言者的观点，再补充你自己的」 |
| 传递粒度 | **全文**传递（讨论保真 > 省钱） |
| 结束机制 | ① 用户随时插话叫停；② 可选按钮「三轮后结束讨论」：点后唤醒上限锁死 3 轮 + 每次唤醒附带「尽量收敛观点，3 轮后结束」提示；③ 不按按钮 → 讨论无限进行（纯讨论不干活，token 可控） |
| 功能位置 | 组织架构页（org_chart.html）：顶栏「讨论室」入口 → 弹窗多选成员 → 讨论视图 |
| 参与资格 | v1 仅「终端托管」成员可选（有进程可唤醒）；引导词成员显示但置灰，提示暂不支持 |

## 2. 交互流程

```
顶栏「讨论室」按钮
  → 弹窗：成员多选（默认勾选全部托管成员）+ 主题输入框 + 「三轮后结束」开关
  → 「开始讨论」→ 进入讨论视图（全屏浮层）

讨论视图：
  ┌────────────────────────────────────────────┐
  │ 讨论主题  ·  [三轮后结束讨论] (可随时点)      │
  ├──────────┬─────────────────────────────────┤
  │ 参与者    │ 聊天流（复用 dsh 消息样式）        │
  │ ● 设计总负责│ 你：主题…                       │
  │ ● DSH2    │ A：我的观点是…                  │
  │ (状态点)   │ B：回应A，我补充…               │
  │          │ …                               │
  ├──────────┴─────────────────────────────────┤
  │ [输入框：插话/继续]          (你随时可插话)    │
  └────────────────────────────────────────────┘
```

- 你插话 = 发言广播进群 + 写入讨论记录，下一位唤醒时自然看到（不打断轮转）。
- 「三轮后结束」点下后：按钮变「⏳ 3 轮后自动结束」，唤醒词附带收敛提示；到达后广播「讨论已结束」。
- 关闭视图 = 讨论仍在后台继续（状态由 server 持有）；重开视图 / 刷新页面恢复（GET state）。

## 3. 后端设计（server.py）

### 3.1 房间状态（进程内，单项目单房间 v1）

```python
_discuss_rooms = {}   # project -> {
#   topic, participants:[agent_id...], history:[{from,text,ts}],
#   turn_idx, round_count, round_limit: None|3, active: bool,
#   busy: bool（当前是否正唤醒某成员）, ended: bool
# }
```

### 3.2 API

| API | 说明 |
|---|---|
| `POST /api/discuss/start` | `{project, participants, topic}` → 建房间 → 立即唤醒第一个成员 → 返回 SSE 流 |
| `POST /api/discuss/stop` | 用户叫停：广播「讨论已结束」、房间置 ended |
| `POST /api/discuss/round-limit` | `{limit: 3 \| null}`：设置/取消三轮按钮（按钮语义） |
| `POST /api/discuss/chat` | 用户插话：写入 history + 广播（继续轮转） |
| `GET /api/discuss/state` | 返回房间当前状态（前端刷新恢复） |

### 3.3 轮转调度 `_discuss_next(project)`

1. 取当前发言者（顺序循环 participants；跳过 user 与非托管成员）。
2. 构造唤醒消息：
   - 身份锚定前缀（复用现有 `_dsh` profile 机制，`--patch` 模型锁不变）
   - 「【讨论室 · 主题】…」
   - 完整讨论记录（每条带发言者名 + 时间，按序）
   - 规则：「请先回应群里最近一位发言者的观点，再补充你自己的。」
   - 若 round_limit 生效：「请尽量收敛观点，3 轮后讨论将结束。」
3. 调 `_dsh_run` 流式转发（SSE：status/thinking/text/final/dsh_error 全复用 v2.19.3 管线）。
4. 发言结束后：追加 history + 广播 `discuss_msg` → 若 round_limit 到达 → 广播「讨论已结束」；否则 `_discuss_next` 继续。
5. 结束/叫停后：busy 释放、active=False。

- 讨论记录**独立存储**（`<项目>/dsh_chat/_discuss_<topic>.json` 或进程内 + 落盘），不污染各成员 1:1 历史。
- 复用现有锁（每成员同时只一个会话），房间唤醒前检查成员忙闲。

## 4. 前端设计（org_chart.html）

- 顶栏：`btn-discuss`「讨论室」，置于「看板」旁。
- 发起弹窗：成员多选列表（托管成员默认勾选；引导词成员置灰 + 提示）、主题输入、三轮开关、开始按钮。
- 讨论视图：全屏浮层。
  - 左栏参与者：名字 + 状态点（思考中 ⏳ / 已发言 ● / 待发言 ○ / 掉线 ✗）。
  - 右侧聊天流：复用 `dsh-msg` 样式（发言者名 + 内容），thinking 折叠块、activity 指示、dsh_error 提示全部复用 v2.19.3。
  - 底部输入框：插话（作为「你」发言进群）；「三轮后结束讨论」按钮（可随时切换）。
  - SSE 订阅 `/api/discuss/start`（或 `chat`）流；`discuss_end` 事件显示结束横幅。
  - 打开/刷新时 `GET /api/discuss/state` 恢复。

## 5. 边界与限制

- v1 参与者仅托管进程；引导词成员置灰（v1.5 做手动代发言：轮到该成员时前端提示用户去粘贴/带回）。
- 单项目单讨论房间（重复发起 → 提示先结束当前房间）。
- 依赖各成员模型可用性（当前 space-bunny-free 已切 DeepSeek/MIMO，白名单内可用）。
- token：全文传递随轮数线性增长——已由「三轮按钮 + 插话叫停」兜底。

## 6. 验证方案

- 用含 ≥2 个托管成员的项目（如 collab-board-dev）实测：
  1. 发起讨论 → A 发言 → B 回应 A（确认上下文带上了 A 的观点）；
  2. 点「三轮后结束」→ 观察到唤醒词带收敛提示 → 3 轮后自动结束广播；
  3. 中途插话 → 下一位发言中能看到你的话；
  4. 刷新页面 → 讨论状态恢复；
  5. 模型不可用成员 → 前端显示 dsh_error 提示、轮转跳过或暂停（按实测决定：v1 先跳过继续）。
- 完成后：CHANGELOG（英文）+ git 提交，本地验收后不发布。
